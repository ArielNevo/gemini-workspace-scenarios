## 1. מה בונים, ולמי

### דוגמה

נועה עובדת בצוות מטה בגוף ציבורי. שמעה על Gemini, אין לה רישיון, והיא לא בטוחה שזה רלוונטי לעבודה שלה. היא נכנסת לאתר, מסמנת "קריאת נהלים" ו"הכנת ישיבות", ומציינת שהקושי הוא כמות החומר. תוך 3–5 דקות היא מקבלת:

- שני או שלושה שימושים שכדאי לה לבדוק, עם הסבר למה הוצעו ("הצענו את זה כי ציינת קריאת נהלים והקושי הוא כמות חומר").
- הדגמה שאפשר ללחוץ בתוכה, על מסמכים מדומים.
- תוכנית להתנסות ראשונה (מה להכין, מה נחשב הצלחה).
- כפתור לבקשת רישיון או להצטרפות להתנסות, שמעביר את תקציר הבחירות שלה לתהליך הארגוני.

בכל המסלול היא רואה בבירור: אין להזין באתר מידע ארגוני.

### המוצר

אתר סטטי בעברית (RTL) שעוזר לעובדי הארגון שעדיין אין להם רישיון לגלות במה Gemini ו-Gemini Notebook (לשעבר NotebookLM) יכולים לעזור בעבודתם, ולבקש רישיון או להתנסות.

- הבטחה לעובד: "גלו איפה Gemini יכול לעזור בעבודה שלכם. ענו על כמה שאלות קצרות, ראו דוגמאות, וקבלו שלושה שימושים שכדאי לכם לבדוק. אין צורך ברישיון כדי להתחיל."
- מיקוד: Gemini (האפליקציה) ו-Gemini Notebook. "Gemini ביישומי Workspace" (לוח הצד ב-Docs, Sheets ועוד) מופיע כאפשרות שלישית, ללא הרחבה. זה אינו מדריך כללי ל-Workspace.
- שמות: בכל מקום שבו מופיע הכלי השני, כתוב "Gemini Notebook (לשעבר NotebookLM)", כדי שמי ששמע על NotebookLM יזהה אותו.
- עקרונות: גילוי לפני רישוי. הליבה עובדת בלי מודל שפה, בלי שרת ובלי חשבון. כנות לגבי מה ידוע ומה לא.

### מה האתר אינו

אינו צ'אטבוט, אינו מקבל מסמכים, אינו מפעיל מודל על תוכן שהמשתמש כתב, ואינו מבטיח חיסכון. הוא מציג דוגמאות והתאמה, ומפנה להתנסות אמיתית בכלי עצמו.

## 2. כללי ברזל

### 2.1 אין להזין מידע ארגוני (חובה בכל הממשק)

האתר חייב לומר למשתמשים, שוב ושוב ובצורה בולטת, שאין להזין בו מידע ארגוני. זו דרישה מרכזית ולא תוספת.

איפה זה מופיע (כל מקום מקבל קומפוננטה אחת, `<OrgDataNotice variant="banner|inline|full" />`):

| מקום | וריאנט | הערות |
|---|---|---|
| פס עליון בכל עמוד ובכל נתיב | banner | קבוע, אינו ניתן לסגירה. נוסח קצר |
| לפני שאלות המסלול (מסך 2) ולפני תיבת החיפוש | inline | מעל הקלט, לא רק בתחתית |
| עמוד התוצאות והכרטיס האישי | inline | כולל הנחיה להתנסות רק בחומר פומבי או מדומה |
| כל דף תרחיש וכל הדגמה | inline | הדגמות מבוססות על חומר מדומה בלבד |
| חשיפה לפני הפעלת "הכוונה חכמה" (סעיף 11) | inline | יחד עם הסבר על מה נשלח |
| תחתית כל עמוד | banner קצר | קישור לעמוד המלא |
| עמוד /notice ("מה אסור להזין ולמה") | full | הסבר מלא |
| README.md | פסקה ראשונה | גם למי שמגיע דרך הריפו |

כללי הטופס:

- אין באתר שדה טקסט חופשי חוץ מתיבת החיפוש. כל שאר הקלט הוא בחירה מרשימות.
- תיבת החיפוש פועלת בדפדפן בלבד. הטקסט אינו נשלח, אינו נשמר ואינו נרשם בשום מקום.
- אם בעתיד יופעל טקסט חופשי בהכוונה החכמה (סעיף 11), חלות עליו הגנות נוספות.

נוסחים קבועים (ב-content/copy.he.json, כדי שבעל המוצר יוכל לערוך. נוסח התחלתי, בלי שינוי משמעות):

```json
{
  "notice.banner": "אין להזין באתר מידע ארגוני, מידע אישי או מידע מוגן. האתר לא מבקש ולא אוסף טקסט חופשי.",
  "notice.inline": "בחרו מתוך האפשרויות בלבד. אל תכתבו כאן מידע ארגוני: לא שמות, לא מספרי תיקים ולא תוכן ממסמכים.",
  "notice.search": "החיפוש פועל בדפדפן שלכם בלבד. חפשו בנושאים כלליים, ואל תכתבו מידע ארגוני או אישי.",
  "notice.afterLicense": "גם אחרי שתקבלו גישה לכלי: התחילו בחומר פומבי או מדומה, ופעלו לפי הנחיות הארגון בנוגע למידע מוגן.",
  "notice.demos": "ההדגמות באתר מבוססות על מסמכים מדומים. אין בהן מידע אמיתי.",
  "notice.footer": "אתר ניסיוני להכרת תרחישי שימוש. אינו מחליף את הנחיות הארגון. אין להזין בו מידע ארגוני."
}
```

עמוד /notice (מלא) כולל:

- מה אסור להזין (רשימה): מידע אישי על עובדים או על אזרחים; מידע מסווג או חסוי; מידע שחל עליו חיסיון משפטי; סודות מסחריים וקניין רוחני; מסמכים פנימיים או תוכנם; כל דבר שלא היית מפרסם באתר ציבורי.
- מה האתר עושה: כל החישוב מתבצע בדפדפן. אין חשבונות, אין עוגיות, אין סקריפטים של צד שלישי. מה שנשמר מקומית נשמר רק אם המשתמש לחץ "שמור".
- אחרי קבלת רישיון: הנוסח notice.afterLicense וקישורים מתצורה: הנחיות הארגון (orgGuidelinesUrl) והמדריך הממשלתי לשימוש אחראי בכלי AI (nationalGuideUrl).
- אל תצטט את המדריך הממשלתי מעבר לקישור וללשון הכללית שלמעלה, כדי לא לייחס לו דברים שלא נבדקו (נספח ב', סעיף 8).

בדיקה אוטומטית (e2e): כל נתיב באתר מכיל את notice.banner. נתיבי המסלול והתוצאות מכילים גם את notice.inline. הבדיקה נכשלת אם נתיב חדש נוסף בלעדיהם.

### 2.2 ריפו ואתר פומביים

- כל מה שבריפו ובאתר גלוי לכל העולם. אסור להכניס: מידע פנימי של הארגון, שמות עובדים, כתובות או מערכות פנימיות, מסמכים אמיתיים, שמות אמיתיים של גופים או חוקים בהקשר של הדגמות, מפתחות סודיים.
- מזהה ארגוני: בכל הטקסטים השתמש ב"הארגון". שם הארגון יופיע רק אם הוגדר ב-site.config.json (orgDisplayName, ריק כברירת מחדל).
- ללא סמל רשמי או לוגו ארגוני. זהות ויזואלית ניטרלית, עם מקום אופציונלי ללוגו בתצורה.
- ללא אינדוקס: `<meta name="robots" content="noindex,nofollow">` ו-robots.txt שאוסר אינדוקס. ברירת מחדל שניתנת לשינוי בתצורה.
- בדיקת תוכן ב-CI (scripts/content-lint): נכשלת על כתובות מייל, מספרי טלפון, רצפי 9 ספרות (תעודת זהות), וכתובות URL שאינן ברשימת content/allowed-domains.json (google.com ותתי-דומיינים, gov.il, github.com, firebase.google.com). בנוסף: אם קיים משתנה סביבה CONTENT_FORBIDDEN_TERMS (רשימה מופרדת בפסיקים, מוגדרת כ-secret בריפו ולא בקוד), הבדיקה נכשלת על כל מונח מהרשימה. כשהמשתנה ריק, הבדיקה מדלגת עליו בלי להיכשל. אל תיצור קובץ של מונחים אסורים בריפו.

### 2.3 אפס עלות ואפס תלות חיצונית

- ריפו חינמי ופומבי, GitHub Pages, GitHub Actions. ללא שרת, ללא בסיס נתונים, ללא חשבון חיוב.
- ללא בקשות רשת לצד שלישי בזמן ריצה (גופנים, אנליטיקה, CDN). גופנים: מערכת, או גופן עברי בקוד פתוח שמתארח בריפו.
- ללא עוגיות. localStorage רק על פעולה יזומה של המשתמש ("שמור").
- הליבה לא תלויה בשום שירות. מודול ההכוונה החכמה (סעיף 11) כבוי כברירת מחדל, ובמצב כבוי אינו טוען קוד ואינו יוצר בקשות רשת.

### 2.4 יושרה בתוכן: מה אסור לטעון

- אין הבטחות חיסכון. אין "תחסכו X שעות". מחשבון הזמן (סעיף 10) הוא המחשה בלבד.
- אין אחוזי התאמה ("92% התאמה"). ההסבר הוא מילולי ושקוף.
- אין טענות על הגנת מידע, אזור נתונים או פרטיות של כלי Google. הן תלויות במהדורה ובהגדרות הארגון. הפנה להנחיות הארגון.
- אין טענות על זמינות ביכולת מסוימת בארגון. רק "קיים אצל Google" (עם מקור ותאריך בדיקה). זמינות בארגון: "תיבדק עם הקצאת הרישיון".
- אין להציג כברירת מחדל: סיכום ישיבות אוטומטי בעברית ב-Meet, Gems בלוח הצד בעברית, הרצת קוד ב-Gemini Notebook (מוגבלת להרשאות מסוימות). ראה נספח ב'.
- תוצרי הכלי אינם סופיים. כל תרחיש כולל "מה צריך לבדוק", ואמירה שהפניות למקורות מאפשרות בדיקה אך אינן מבטיחות שהמסקנה נכונה.
- הבחנה בין שלוש רמות בכל תרחיש (סעיף 5): קיים אצל Google, כלול בחבילה שתוקצה, נבדק בסביבת הארגון.

### 2.5 עברית, RTL ונגישות

- `<html lang="he" dir="rtl">`. CSS עם מאפיינים לוגיים (margin-inline-start ולא margin-left).
- מונחים באנגלית (Gemini, Gemini Notebook) עטופים ב-`<bdi>` או dir="ltr" כדי שלא יתהפכו.
- נגישות ברמת WCAG 2.2 AA: ניווט מלא במקלדת, חיווי פוקוס ברור, ניגודיות, aria-live להצגת תוצאות, תוויות לכל בקרה, כיבוד prefers-reduced-motion, תוכן שאינו תלוי בצבע או בסרטון.
- מובייל תחילה. מסך 360px חייב לעבוד.

### 2.6 הליבה בלי מודל

כל החוויה המתוארת בסעיף 8 חייבת לעבוד בלי שום מודל שפה וללא חיבור אינטרנט מעבר לטעינת הדף. הכוונה חכמה היא תוספת (סעיף 11).

## 3. טכנולוגיה וארכיטקטורה

| תחום | בחירה |
|---|---|
| בנייה | Vite + React + TypeScript (strict). גרסאות עדכניות לפי התיעוד |
| ניתוב | HashRouter, כדי לא להזדקק ל-404 מותאם ב-GitHub Pages. האתר חייב לעבוד גם ב-`https://<user>.github.io/<repo>/` וגם בשורש דומיין מותאם (base מתצורה) |
| עיצוב | CSS רגיל עם משתני CSS ומאפיינים לוגיים. בלי ספריות UI כבדות. תמיכה במצב כהה ובהדפסה |
| מצב | React context + reducer. שמירה ל-localStorage רק בלחיצה על "שמור" |
| חיפוש | MiniSearch, עם נרמול עברי (סעיף 9) |
| ולידציה | Zod לסכמות תוכן. נבדק ב-CI ובפיתוח |
| בדיקות | Vitest (יחידה), Playwright + axe (e2e ונגישות), ESLint, Prettier |
| פריסה | GitHub Actions → GitHub Pages (פעולות רשמיות) |
| אבטחה | CSP דרך `<meta>` (ללא inline scripts), referrer: no-referrer, rel="noopener noreferrer" בקישורים חיצוניים, סימון ויזואלי לקישור שיוצא מהאתר |

- ביצועים: טעינת נתיבים עצלה (lazy). יעד: טעינה ראשונה מתחת ל-200KB gzip, ו-Lighthouse מעל 90 בכל הקטגוריות.
- תוכן: קבצי JSON/Markdown בריפו, נטענים בזמן build (import.meta.glob). אין קריאות רשת לתוכן.
- חיבור מודל: מאחורי ממשק Recommender (סעיף 11). בדגל כבוי הקוד לא נטען כלל (import() דינמי, צ'אנק נפרד).
- אנליטיקה: אין. ממשק track(event) ריק כברירת מחדל, כדי שבעתיד אפשר יהיה לחבר מתאם מאושר בלי לשנות קוד.

## 5. מודל התוכן

### 5.1 סכמת תרחיש (content/scenarios/&lt;id&gt;.json)

```ts
type Tool = 'gemini' | 'gemini-notebook' | 'gemini-in-workspace-apps';
type Family = 'understand' | 'compare' | 'write' | 'learn';

interface Scenario {
  id: string;
  family: Family;
  title: string;
  userNeed: string;
  tool: Tool;
  alternateTool?: Tool;
  whatYouGet: string;
  tags: {
    tasks: string[];
    difficulties: string[];
    materials: string[];
    outputs: string[];
    roles?: string[];
    frequency?: string[];
  };
  priority: number;
  firstExperiment: {
    materialSuggestion: string;
    steps: string[];
    successCriteria: string[];
    timeBoxMinutes: number;
  };
```
